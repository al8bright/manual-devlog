# 오늘의 목표와 맥락

로컬에서만 쓰던 **수동 개발로그 작성 스킬**을 다른 사람도 설치해 쓸 수 있는 형태로 공개하는 것이 목표였다.

기존 스킬은 Codex와 Claude Code 양쪽에 각각 복사해 둔 상태였고, 세션 앞부분에서 두 사본의 문서 규칙(`제목:` / `태그:` 헤더 뒤에 `#` 대분류가 오는 구조)을 동일하게 맞추는 작업까지 끝낸 뒤였다. 남은 문제는 배포 경로였다. 스킬 파일을 수동으로 복사해 달라고 안내하는 대신, **한 줄 명령으로 설치되는 표준 방식**을 쓰고 싶었다.

조사 결과 `npx skills` CLI가 SKILL.md 기반 Agent Skills 표준을 지원하고, 설치 대상 에이전트를 Codex와 Claude Code로 각각 지정할 수 있다는 점을 확인했다. 이 방식을 전제로 공개 저장소를 구성하기로 했다.

# 구현한 내용

## 저장소 분리

작업 자체는 기존 서비스 프로젝트 세션 안에서 시작했지만, **그 저장소에 원격을 추가하지 않았다.** 해당 프로젝트의 `origin`은 이미 다른 서비스 저장소를 가리키고 있었기 때문에, 여기에 공개 스킬용 원격을 붙이면 두 저장소가 뒤섞일 위험이 있었다. 대신 공개용 저장소를 별도 폴더로 두고 그 안에서만 커밋과 푸시를 진행했다.

## 스킬 폴더 구성

저장소 루트 아래에 `manual-devlog/SKILL.md` 하나만 두는 구조로 시작했다. `npx skills add <repo> --skill manual-devlog` 형태로 설치할 때 스킬 이름과 폴더 이름이 그대로 대응되도록 하기 위해서다.

SKILL.md에는 다음 규칙을 명시했다.

- 발행하지 않고 **편집 가능한 Markdown 초안만** 만든다. 업로드 API 호출, GitHub 수집, 저장된 외부 자격 증명 사용을 모두 금지한다.
- 출력 경로는 프로젝트 루트의 `devlogs/`이며, `docs/`에는 절대 쓰지 않는다.
- 파일명은 `YYYYMMDD_[N]_제목.md`이고, 같은 날짜 파일이 있으면 순번을 올린다.
- 본문 섹션은 근거가 있을 때만 사용한다. 특히 `# 문제와 해결`은 실제 문제가 있었던 경우에만 넣는다.

## README 작성

푸시가 끝난 뒤 설치 안내를 담은 README를 추가했다. 구성은 설치 명령, 옵션 의미 표, 사용법 트리거 예시, 결과물 형식, 수동 설치 경로 순이다.

전역 설치 명령은 다음과 같다.

```bash
npx skills add al8bright/manual-devlog --skill manual-devlog -g -a codex -a claude-code --copy -y
```

`--copy`를 기본 안내에 포함한 이유는 Windows 환경 때문이다. 심볼릭 링크 생성은 권한 설정에 따라 실패할 수 있어서, 실제 파일 복사가 더 안전한 기본값이라고 판단했다.

# 설계와 판단

## "무엇을 하지 않나"를 README 상단에 배치

README에서 기능 설명 바로 다음에 **하지 않는 일** 목록을 넣었다. 이 스킬은 개발로그를 다루기 때문에 설치하는 쪽 입장에서 "내 코드나 커밋을 어디로 보내는 것 아닌가"라는 의심이 자연스럽다. 발행하지 않음, 수집하지 않음, 자격 증명 사용하지 않음을 앞에 못 박아 두는 편이 설치 결정에 더 도움이 된다고 봤다.

## 라이선스 섹션을 일부러 넣지 않음

README 초안에는 MIT 라이선스 섹션이 있었지만 **삭제했다.** LICENSE 파일이 저장소에 없는 상태에서 README에만 "MIT"라고 적으면 근거 없는 선언이 된다. 저작권자 표기를 임의로 만들어 넣는 것도 적절하지 않다고 판단해, 라이선스는 별도 확인 후 파일과 함께 추가하기로 남겨 두었다.

# 문제와 해결

## 첫 푸시가 권한 오류로 실패

첫 커밋을 만든 뒤 푸시하자 저장소 접근 권한 오류가 났다. 처음에는 GitHub CLI에 인증된 계정이 대상 저장소의 소유 계정과 다른 점을 원인으로 의심했지만, **실제 원인은 원격 URL과 SSH 설정의 불일치**였다.

원격 주소가 `github.com` 호스트를 그대로 쓰고 있었는데, SSH 설정에서 그 호스트는 다른 계정용 키에 매핑되어 있었다. 즉 인증 자체는 성공하지만 대상 저장소에 권한이 없는 계정으로 접속하고 있었다.

해결은 이미 설정되어 있던 **계정별 SSH 호스트 별칭을 쓰도록 원격 URL을 교체**하는 것이었다.

```bash
git remote set-url origin git@github-al8bright:al8bright/manual-devlog.git
git push -u origin main
```

같은 커밋을 그대로 다시 밀어 성공했다. 커밋을 새로 만들거나 히스토리를 손댈 필요는 없었다. 계정이 여러 개인 환경에서는 **원격 URL의 호스트 부분을 먼저 확인**하는 것이 권한 오류의 가장 빠른 진단 경로라는 점을 확인했다.

# 검증한 내용

- 스킬 정의는 skill-creator의 검증 스크립트로 확인해 `Skill is valid!` 결과를 받았다.
- 첫 커밋(`e682960 feat: add manual devlog skill`)을 원격 `main`에 푸시해 브랜치가 새로 생성되는 것을 확인했다.
- README 커밋(`d9eeda0 [Behavioral] docs: 스킬 설치·사용 안내 README 추가`)을 푸시한 뒤 `main`이 원격과 동기화된 상태(`## main...origin/main`)임을 확인했다.

다만 **`npx skills add` 명령을 실제로 실행해 설치가 성공하는지는 아직 검증하지 않았다.** 현재까지 확인된 것은 저장소 구조와 스킬 정의의 유효성까지다.
